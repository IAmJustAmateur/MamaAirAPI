## Как продолжить

1. Прочитать этот файл, CODEX_HANDOFF.md и применимые AGENTS.md, если появились.
2. Проверить git status и содержимое изменений. Создать новую ветку из текущего
   состояния, чтобы не потерять незакоммиченные файлы:

   ```powershell
   git switch -c codex/privacy-policy-draft
   git fetch origin
   ```

   Если ветка уже существует или база изменилась, сначала разобраться, не сбрасывать
   рабочую папку. Сохранить чужое изменение legacy-скрипта.
3. Перечитать текст политики и проверить точность относительно актуального backend.
   Не расширять задачу до изменения согласий, хранения или удаления без необходимости.
4. Запустить system check, тесты страницы, полный набор и migration drift check.
5. Завершить отладку и выполнить реальный Chromium E2E. Осмотреть скриншоты
   `.e2e-artifacts/privacy/mobile.png` и `desktop.png`, если тест создаст их.
   Локальный WSGI smoke не считать проверкой production ASGI/HTTPS deployment.
6. Проверить diff только нашей задачи и показать пользователю результаты/ограничения.
7. После обсуждения сделать выборочный git add, commit, push и PR. У remote перед push
   проверить URL. Чужой legacy-скрипт, логи, .env, БД и артефакты не включать.
8. Deploy выполнять по актуальной процедуре проекта. После deploy проверить публичный
   `/privacy-policy` и рабочую ссылку на `/delete-account`. Черновик пока не подавать
   в магазины как окончательную политику.
